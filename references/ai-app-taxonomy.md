# AI 应用开发分类轴

来源：王工的「AI 应用开发_架构全流程」notes（独立管理，本库只引用不复制，不写入任何本机路径）。一条经验的完整坐标 = **层 × 模块 × 阶段**，三者不是父子关系，是交叉的坐标轴。

## 阶段（时间轴与门禁）

| 值 | 名称 | 典型内容 |
|---|---|---|
| `S1 需求分析` | 场景与指标 | 场景画像、任务形态判定、语料审计、NFR、黄金集初稿、PoC |
| `S2 技术选型` | 选型与契约 | 模型路由、编排框架、存储检索、协议、ADR |
| `S3 工程规范` | 规范与骨架 | 仓库结构、代码规范、配置、日志、错误模型、依赖注入、CI、防退化 |
| `S4 模块开发` | 纵向切片 | 模型网关、摄取、检索、Agent、Prompt、记忆、护栏、可观测、API |
| `S5 测试评估` | 测试与评估 | 测试金字塔、黄金集、离线评估、Judge 校准、回归门禁、调优 |
| `S6 部署上线` | 部署与回滚 | 环境、容器、迁移与索引切换、发布策略、健康检查、回滚演练 |
| `S7 运维迭代` | 运行与闭环 | SLO、追踪与成本、事故响应、反馈闭环、知识运营、模型升级 |
| `跨阶段` | 贯穿 | 方法论、协作流程、通用原则 |

## 模块（业务能力，横跨四层）

`Conversation` 会话 · `Knowledge` 知识 · `Retrieval` 检索 · `Agent` 智能体 · `Governance` 治理 · `Platform` 平台 · `通用`

## 分层（代码归属与依赖方向）

`Interface` 接口 · `Application` 应用 · `Domain` 领域 · `Infrastructure` 基础设施 · `部署资产` · `通用`

依赖方向：Interface → Application → Domain ← Infrastructure；`bootstrap` 是唯一允许同时依赖四层的组合根。

## 归类规则

1. frontmatter 的 `stage` / `module` / `layer` 填**主坐标**，取这条卡里占比最大的一个。
2. 每条经验、每个反例必须写自己的 `坐标`，允许与主坐标不同。
3. 一条经验同时影响多层或多模块时，写主语坐标，其余在「做法」里点明。
4. 与代码结构无关的内容（流程、规范、协作）写 `通用`。
5. 拿不准阶段时按「这条经验在什么时候能救你」归类，不按它涉及的技术归类。

## 覆盖边界

7 个阶段只覆盖**工程生命周期**，不覆盖 AI 应用开发的全部知识。以下内容不硬塞：

| 内容 | 归到 |
|---|---|
| 安全、合规、成本、配额 | `跨阶段`，具体写进 tags |
| 领域业务规则、行业口径 | `跨阶段` + `通用`，tags 写领域 |
| 团队协作、评审、沟通 | `跨阶段` + `通用` |
| 模型训练、微调、蒸馏 | 按语境归 `S2` 或 `S4` |
| 产品运营、用户反馈 | `S7` 或 `跨阶段` |
| 纯技术专题（切分、重排、Agent 循环） | 由 `module` 承载，`stage` 写它最容易出问题的阶段 |

## 项目未按标准流程

坐标表达「这条经验在什么时候能救你」，**不表示项目执行过该阶段**。

- 项目跳过 S3，仍可能产出 S3 的经验：踩到跨层直连、配置散落时，这条经验就是 S3。
- 项目没写 ADR，仍可能产出 S2 的经验：选型比较维度本身就是 S2。
- 项目没上线，S6 的经验照样成立：它来自一次回滚演练或一次索引切换失败。

## 降级规则（按顺序执行）

1. 能明确对应阶段 → 用对应阶段。
2. 横切多个阶段 → `跨阶段`。
3. 与阶段无关 → `跨阶段` + `通用`。
4. 仍然无法判断 → `跨阶段`，并在 tags 写清主题。

**禁止为了填满枚举而硬凑**。归错阶段比归到 `跨阶段` 危害更大：前者会让检索永远漏掉或误命中，后者只是精度降低。

## 空阶段不影响使用

阶段是检索维度，不是流程检查表。某个项目没有 S6 经验，只是该阶段的分组为空，不影响其他阶段的读取与聚合。知识库建页时按需生成，不为空阶段建空页。

## 示例

| 经验 | 坐标 | 类型 |
|---|---|---|
| pgvector 适配器超时未重试导致索引中断 | S4 模块开发 / Infrastructure / Knowledge | pitfall |
| 重排阈值按查询类型分组标定 | S5 测试评估 / Application / Retrieval | pattern |
| 黄金集必须先于第一个 API | S1 需求分析 / 通用 / 通用 | constraint |
| 层优先而非功能优先的目录编排 | S3 工程规范 / 通用 / 通用 | decision |
| 索引切换必须版本化 + 别名 + 可回滚 | S6 部署上线 / 部署资产 / Knowledge | constraint |

## 与知识库的关系

坐标是聚合键，不是目录结构：

- **主坐标只有 `stage`**：数字分身按 `S1→S7` 归纳到 `02-记忆/S*/`；`跨阶段` 对应分身的 `通用/`。
- `layer` / `module` 降为标签，用于检索与判断依赖是否越界，**不进分身目录**（否则要建 7×6 个目录）。
- 知识库不建主题页；卡片的聚合由 AI 现场读目录完成。
