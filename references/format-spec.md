# 经验卡格式规范（v1）

## 1. 文件位置与命名

- 目录：`<KB>/<project_id>/cards/`（由 `scripts/resolve_project.py` 解析）
- 文件名：`YYYYMMDD-<主题>.md`，主题用小写英文短横线，不超过 6 个词
- 一个文件 = 一次抽取 = 一个可独立理解的主题

## 2. frontmatter

```yaml
schema_version: 1
id: 20261104-rerank-threshold
title: 重排阈值必须按查询类型分组标定
date: 2026-11-04
source: 对话 | 文件:docs/adr/003-rerank.md
background: 用于 Retrieval 模块召回不足时的阈值调整
stage: S5 测试评估
module: Retrieval
layer: Application
type: pitfall
status: active
confidence: 0.8
tags: [重排, 阈值, 评估集]
supersedes: []
superseded_by: []
related: []
```

| 字段 | 必填 | 说明 |
|---|---|---|
| schema_version | 是 | 模板版本，当前固定为 `1`；升级模板时用它做迁移判断 |
| id | 是 | 与文件名一致（去 `.md`） |
| title | 是 | ≤ 20 字，写结论不写主题词 |
| date | 是 | 抽取日期 `YYYY-MM-DD` |
| source | 是 | `对话` 或 `文件:<路径>`，多个用逗号分隔 |
| background | 是 | 一句话：用于「哪个模块/能力」的「什么问题」 |
| stage | 是 | 主阶段，取值见 [ai-app-taxonomy.md](ai-app-taxonomy.md) |
| module | 否 | 主模块，跨模块写 `通用` |
| layer | 否 | 主分层，非代码内容写 `通用` |
| type | 是 | 主类型，见下表 |
| status | 是 | `active` / `superseded` / `deprecated` |
| confidence | 是 | 文件级整体置信度，0.3–0.9 |
| tags | 是 | 2–5 个检索词 |
| supersedes | 否 | 本卡取代的旧卡 id |
| superseded_by | 否 | 取代本卡的 id，仅由后写卡填入 |
| related | 否 | 补充或冲突的卡 id |

`type` 取值：

| 值 | 含义 |
|---|---|
| `decision` | 做过的取舍，含备选与否决理由 |
| `pitfall` | 踩过的坑，含现象、根因、代价 |
| `pattern` | 可复用的固定做法 |
| `constraint` | 边界、红线、门禁 |
| `path` | 验证过的有效路径 |

## 3. 正文结构

固定 6 节，顺序不可变。第 3、6 节可省略。

```markdown
## 1. 结论
<1–3 行。读完就知道该做什么。>

## 2. 经验

### E1 <≤20 字标题>
- 坐标：S5 测试评估 / Application / Retrieval｜类型：pitfall
- 触发：<什么场景、什么信号出现时>
- 做法：<一句话结论，可含步骤编号>
- 原因：<为什么成立>
- 证据：<复现 N 次 / 报错原文 / 文件路径:行 / 对话轮次>
- 置信度：<0.3–0.9>
- 背景：用于 <模块或能力> 的 <问题>

### E2 ...

## 3. 失败与反例

### F1 <≤20 字标题>
- 坐标：<阶段 / 层 / 模块>
- 现象：<可观测表现>
- 根因：<真正原因，不是表面原因>
- 代价：<浪费了什么：时间 / 资源 / 返工>
- 规避：<一条可执行规则>

## 4. 复用清单
- [ ] <可直接执行的动作>

## 5. 边界
- 适用：<成立条件>
- 不适用：<失效条件>
- 失效信号：<出现即应重新评估的现象>

## 6. 关联
- <id>：<补充 / 冲突 / 取代>
```

坐标是这套卡的核心索引：一份卡可以横跨多个阶段与模块，但每条经验必须自带完整坐标，便于知识库按「层 × 模块 × 阶段」聚合，也便于数字分身按流程取用。

`decision` 类型必须在「原因」里压缩写明备选与否决理由，一行内完成，例如：

```
- 原因：选 A 而非 B/C——A 支持流式，B 延迟高，C 无重试
```

不新增备选字段，避免字段数随类型变化、破坏机器解析。

## 4. 规模上限

| 项 | 上限 |
|---|---|
| 单个文件 | 150 行 |
| 单条经验 | 8 行（含标题，固定字段不得展开） |
| 经验条目 | 10 条 |
| 失败反例 | 5 条 |
| 复用清单 | 8 条 |
| 结论 | 3 行 |

超过上限先合并：同根因合并、同场景合并、可推导项删除。合并后仍超限才拆分。

### 深度边界

- 卡记判断，源记过程：一条经验只回答「下次遇到什么场景、该怎么做」
- 操作步骤进「复用清单」，最多 8 条
- 代码片段、长配置、完整推演不进卡，用 `证据` 指向源文件路径
- 内容丰富的经验拆成多个原子条目，不把单个字段写长

## 5. 拆分规则

满足任一条件即拆分：

1. 可独立复用的主题 ≥ 4 个
2. 文件超过 150 行
3. 单一主题正文超过 60 行
4. 输入跨越两个以上无关任务

拆分原则：

- 按**主题边界**切，不按时间顺序切
- 每个子文件自带完整结论、边界、frontmatter
- 子文件用主题命名，不用 `part1`/`part2`
- 双向填写 `related`
- 全局共识放主文件，子文件只写本主题差异

## 6. 修订与取代

经验卡是可追溯证据，正文与证据**永不修改**。

| 场景 | 做法 |
|---|---|
| 发现旧结论有误 | 新建一张卡，`supersedes` 填旧 id；旧卡仅改 frontmatter：`status: superseded`、`superseded_by` 填新 id |
| 旧结论只是过时 | 同上，新卡 `type: constraint`，注明失效条件 |
| 新旧冲突未定 | 两张都保持 `active`，各自 `related` 互指，由知识库层裁决 |
| 需要补充而非否定 | 新建卡，`related` 指向原卡，不改原卡 |
| 分类轴调整或归错 | 只校正 frontmatter 的 `stage` / `module` / `layer` / `tags`，正文不动 |

可修改：frontmatter 的 `status`、`superseded_by`、`stage`、`module`、`layer`、`tags`、`related`。
不可修改：正文（结论 / 经验 / 反例 / 清单 / 边界）与证据。

元数据可校正，是因为分类轴会随项目演进；正文必须不可变，是因为它是当时的证据。把两者分开，才能既保证可追溯，又不让早期归错永久固化。

## 7. 禁止项

- 时间线、过程还原、对话摘录
- 「我们」「我觉得」等主观主语
- 无证据的断言（可降为 `confidence: 0.3` 并标注待验证）
- 可直接从代码或文档读到的内容
- 同一结论在不同条目重复出现
