## 1. 结论

经验资产的复用价值取决于三个要素：条目是否原子、是否带坐标与证据、是否有置信度。整篇总结、无证据结论、一次新建都会让资产在第二次使用时失效。

## 2. 经验

### E1 观测用 hook，触发用 skill
- 坐标：跨阶段 / 通用 / 通用｜类型：pattern
- 触发：需要稳定捕获会话事实时
- 做法：PreToolUse/PostToolUse 采集原始事实，skill 只在人工判定期调用
- 原因：skill 触发是概率行为（社区实测 50–80%），hook 是事件驱动，100% 触发
- 证据：affaan-m/ECC continuous-learning-v2 演进记录指出 v1 靠 skill 观测不可靠
- 置信度：0.8
- 背景：用于自动归档会话经验

### E2 一条经验一个块，固定 8 行
- 坐标：跨阶段 / 通用 / 通用｜类型：pattern
- 触发：即将把多结论写成连续段落时
- 做法：每条固定「标题/坐标/触发/做法/原因/证据/置信度/背景」，单字段单行
- 原因：字段固定才能被知识库按坐标与字段解析，段落写法只能人工重读
- 证据：本对话确定的结构；对照 vercel/ai adr-skill 的固定节要求
- 置信度：0.7
- 背景：用于经验卡被数字分身机械解析

### E3 决策要写成可执行规格
- 坐标：S2 技术选型 / 通用 / 通用｜类型：constraint
- 触发：记录技术选型或架构决策时
- 做法：必须包含非目标、实施涉及的路径、验收判据；缺任一项则该条不可执行
- 原因：叙述型决策后人只能"知道"，无法"照做"，代理同样无法照做
- 证据：vercel/ai skills/adr-skill 的 agent-readiness 要求
- 置信度：0.85
- 背景：用于 AI 应用开发中的架构决策沉淀

### E4 冲突用取代，不用改写
- 坐标：跨阶段 / 通用 / 通用｜类型：constraint
- 触发：新结论与已有经验卡不一致时
- 做法：旧卡正文不动，新建卡填 `supersedes`，旧卡只改 `status` 与 `superseded_by`
- 原因：改正文会销毁原始证据，后续无法判断哪版在什么条件下成立
- 证据：Karpathy LLM Wiki 的原始层不可变约束；本对话修订规则
- 置信度：0.8
- 背景：用于知识库长期可维护与可追溯

### E5 三个模块先解耦
- 坐标：跨阶段 / 通用 / 通用｜类型：decision
- 触发：设计经验总结、知识库、数字分身时
- 做法：第一期只让经验总结产出经验卡，不建索引、不建检索、不写项目规则
- 原因：三模块耦合会使规范随检索需求变更，导致历史资产失效
- 证据：本对话用户明确要求；ECC 因采集/分析/演化耦合而复杂度失控
- 置信度：0.7
- 背景：用于三模块体系分期落地

## 3. 失败与反例

### F1 直接安装通用记忆插件
- 坐标：跨阶段 / 通用 / 通用
- 现象：装 claude-mem 后能回忆会话，但拿不出可复用规范
- 根因：记忆是"发生过什么"，经验是"下次该怎么做"，存储目标不同
- 代价：多一套数据库与注入逻辑，仍要人工重写经验
- 规避：记忆类工具只用于上下文续接，经验抽取单独实现

### F2 整篇对话压成一个 md
- 坐标：跨阶段 / 通用 / 通用
- 现象：文件迅速超过数百行，检索时只能整篇加载
- 根因：不同主题被强制同文件，缺少原子边界
- 代价：token 成本上升，且无法按需精确引用
- 规避：按主题拆分，单文件 ≤150 行，单条 ≤8 行

### F3 依赖 ECC 后台 observer 自动分析
- 坐标：S7 运维迭代 / 通用 / 通用
- 现象：Windows 上 observer 报告启动成功但从不产出
- 根因：hook 派生的后台进程随 hook 退出被 Job Object 终止
- 代价：以为已开启自动学习，实际零产出
- 规避：Windows 下只用同步 hook 或手动调用，后台分析需独立常驻进程

## 5. 边界

- 适用：单次任务、调试、评审、方案讨论结束后的经验归档
- 不适用：需要实时上下文续接的场景（该用记忆类工具）
- 失效信号：同一主题卡开始互相矛盾且无法裁决时，应回到知识库层建立裁决机制
